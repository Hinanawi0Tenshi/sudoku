## 新需求：奖励机制（通关得点数 → 抽卡池 → 收集人物图）—— 只出了方案，未动代码
- 用户诉求：通关拿抽奖点数，开卡池抽人物图像。我先读了全项目再给方案。
- 关键洞察：`19-app.js` 的 `onWin()` 是唯一胜利结算入口（手动落子/提示执行/自动求解都汇到这里），
  加点数只需改一处；`11-store.js` 的 `read()` 用 `Object.assign` 兜默认值，state 加新字段不会崩老存档。
- 已定参数（用户拍板）：**正常档节奏** = 单抽 50 / 十连 400；**重复卡转碎片、可指定兑换**。
- 用户的两个核心疑问（也是方案重点）：① 图像怎么获取 ② 除图像外还给什么奖励
- 方案结论：
  - 图像 → **manifest 驱动 + 程序化卡面兜底**。`art` 字段为空就回落到 CSS 生成的卡面，
    所以出图不是阻塞项，图片随时可换且不用改代码。自出图走 ComfyUI 量产（半身/居中/同背景/同色调，
    长边 720px WebP q80，≤100KB/张），先做 12 张（SSR2/SR3/R3/N4）。
  - 非图像奖励 → **棋盘皮肤是最优解**（本质就是几组 CSS 变量，零素材体积、可即时感知、
    与图鉴 UI 天然共用）。三层结构：抽卡池(立绘70%/皮肤18%/补签券12%) + 通关确定性解锁皮肤 + 图鉴成就。
  - 防刷必须做：以 `givens` 字符串指纹为准，同一题面只有首通给全额（否则「重来」= 无限刷分）。
- **技术坑（重要）**：卡池 manifest **不能放 .json 用 fetch 读** —— 项目要支持双击 index.html，
  `file://` 下 fetch 本地文件被同源策略拦。必须内联成 js 常量（跟 `SD.Bank.LIST` 一样）。
- 产出：`docs/奖励机制方案.md`（完整设计稿 v0.1，待用户确认后开工 P0）。
