# 数独 · 奖励机制方案

> 状态：设计稿 v0.1 ｜ 2026-10-02
> 需求：通关得点数 → 开卡池 → 收集人物图像

已定参数：**正常档节奏**（单抽 50 / 十连 400）；**重复卡转碎片、可指定兑换**。

---

## 0. 一句话

通关产出「点数」，点数抽卡；卡池里是**人物立绘 + 棋盘皮肤 + 补签券**；收集进度反过来驱动「再来一局」。

---

## 1. 先划三条硬边界

这个项目的气质是克制的——关于页写着「没有账号、没有服务器、没有埋点」。加抽卡最容易丢掉这个气质，所以先钉死三条：

1. **纯本地**：不引服务器、不做账号、不做排行榜。全部落在现有 `localStorage` 的同一个 key 里。
2. **不碰钱**：没有付费、没有限时池、没有现实兑换。这是单机游戏，抽卡只是「通关的仪式感」。
3. **奖励不改解题**：卡池不产出「更多提示次数」「跳过」「自动解」。唯一带功能的道具是**补签券**，它只影响每日挑战的连续天数，不碰任何一局的难度与判定。

守住这三条，抽卡就只是数独外面多穿了一层衣服。

## 2. 图像从哪来

### 2.1 四条路径

| 路径 | 一次性成本 | 风格统一度 | 版权 | 适用阶段 |
|---|---|---|---|---|
| **自己用 ComfyUI/SD 批量出** | 中（约半天出图） | 高（同 LoRA + 同风格 prompt） | 干净 | 正式版 |
| WorkBuddy 图像生成 | 低 | 低（跨次角色不一致） | 干净 | 应急占位 |
| **程序化卡面（CSS 生成）** | 极低 | 完美统一 | 无素材依赖 | 开发期 / 永久兜底 |
| 公版素材库 | 低 | 差 | 需逐张核对 | 不推荐 |

### 2.2 推荐组合：manifest 驱动 + 程序化兜底

卡池数据**不依赖图片存在**。manifest 里每张卡是 `id / name / rarity / art`，`art` 为空时自动回落到程序化卡面——纯色块 + 网格纹理 + 大字号名字 + 稀有度描边。

这么做的好处：

- 今天就能把功能跑通、直接上线玩，不用等图
- 哪天图出好了，往 `assets/cards/` 一丢、把 `art` 字段填上即可，**一行代码都不用改**
- 出图永远不是这个功能的阻塞项

### 2.3 ComfyUI 生产规格书

如果走自己出图这条路，按这份规格来，出来的东西才像「一套卡池」：

**构图约束（比画得多好看更重要）**

- 全部**半身、居中、视线看镜头**——这是「卡池感」的唯一来源
- 全部**同一类背景**（纯色 / 纯白 / 同一套光效），不要一张室内一张野外
- 全部**同一套光照与色调**，后期可再统一一次

**Prompt 骨架**

```
positive:
  (masterpiece, best quality:1.2), {角色 LoRA 触发词}, 1girl, upper body,
  looking at viewer, centered composition, simple solid background,
  soft cel shading, clean lineart, card game illustration
negative:
  (worst quality, low quality:1.4), text, watermark, signature,
  multiple views, border, frame, busy background, extra limbs
```

- 同一个基础 seed 家族 + 同一组采样参数跑完整套，风格漂移最小
- 一次跑 4 张 × 20 组 = 80 张候选，够挑出 24 张能用的

**输出规格**

- 原图 896×1152（7:9）或 1024×1536（2:3）
- 落盘前统一压到**长边 720px、WebP q=80**，单张目标 ≤ 100KB
- 命名 `assets/cards/{id}.webp`，id 用两位数（`01.webp` … `24.webp`）
- 图鉴网格用 `loading="lazy"` + 固定 `aspect-ratio` 容器，避免布局抖动

**批量压缩（Windows）**

```bash
i=1
for f in raw/*.png; do
  ffmpeg -y -loglevel error -i "$f" \
    -vf "scale=-1:720" -quality 82 \
    "assets/cards/$(printf '%02d' $i).webp"
  i=$((i+1))
done
```

### 2.4 卡池规模

**先做 12 张**（SSR 2 / SR 3 / R 3 / N 4）。12 张是「能感觉到在收集」的最小规模，出图工时压到一次能做完的量。跑顺了再扩到 24–36 张。

## 3. 除了图像还给什么

纯抽立绘的毛病是：抽完就没了，图鉴一满这功能就死了。所以要三层叠起来。

### 第一层 · 抽卡池（随机）

人物立绘 **70%** / 棋盘皮肤 **18%** / 补签券 **12%**

**棋盘皮肤是最优的非图像奖励**：

- 可感知——抽到当场就能换上看效果，即时反馈
- 成本低——本质就是几组 CSS 变量（`--box-line`、`--box-tint`、`--given`、`--user`、`--surface`），不增加任何素材体积
- 跟收集逻辑天然一致——皮肤收藏和立绘收藏可以共用同一套图鉴 UI

拟五款：**和纸 / 木质 / 蓝图 / 霓虹 / 星空**

### 第二层 · 通关确定性解锁

首次通关每个难度，直接点亮对应皮肤：

| 难度 | 奖励 |
|---|---|
| 入门 | 和纸 |
| 中等 | 木质 |
| 困难 | 蓝图 |
| 专家 | 霓虹 |
| 大师 | 星空 |

意义：「挑战更高难度」终于有了一个**不靠运气**的回报。纯抽卡的话高手和休闲玩家体验一样，这条把两者拉开了。

### 第三层 · 图鉴成就

- 集齐全部 N 卡 → 解锁一张专属 SSR（只有集齐才拿得到，抽不出来）
- 集齐 8 张 SR 以上 → 首页徽章 + 称号
- 累计十连 5 次 → 送一次免费十连

意义：解决「图鉴卡在八成」的长尾问题。

### 成就系统（点数的第二来源）

- 零提示通关 ×10 → +300 点
- 连续 7 天每日挑战 → +500 点 + 补签券 ×3

跟抽卡解耦，独立产出点数。

## 4. 数值

### 4.1 点数产出

| 难度 | 基础分 |
|---|---|
| 入门 | 15 |
| 中等 | 30 |
| 困难 | 60 |
| 专家 | 120 |
| 大师 | 200 |

乘区（可叠乘）：

| 条件 | 系数 |
|---|---|
| 零提示 | ×1.5 |
| 零错误 | ×1.2 |
| 每日挑战 | ×1.5 |
| 重复通关同一题面 | ×0.2 |

**特例**：用过「自动求解」的局，只给基础分的 **15%**，其余乘区一律不叠。

**防刷是必须的**：以 `givens` 字符串做指纹，同一题面只在**首次通关**给全额。否则「重来」按钮就是无限刷分机。

> 中等难度 · 零提示零错误 · 首通 = 30 × 1.5 × 1.2 = **54 点**

### 4.2 抽卡定价

- 单抽 **50 点**
- 十连 **400 点**（9 折）

按每天 3 局中等难度算 ≈ 162 点/天 → **约 1 局一抽、2.5 天一次十连**。

### 4.3 概率与保底

| 稀有度 | 概率 | 重复转碎片 |
|---|---|---|
| SSR | 3% | 20 |
| SR | 12% | 8 |
| R | 35% | 3 |
| N | 50% | 1 |

- **十连保底**：至少 1 张 SR 以上
- **大保底**：累计 60 抽必出 SSR，出货后计数归零
- 概率与保底在抽卡页正文明示，不藏

### 4.4 碎片兑换

攒够碎片可**直接指定**兑换某一张卡，定价 = 该稀有度重复返碎片 × 10：

| 稀有度 | 兑换价 |
|---|---|
| SSR | 200 |
| SR | 80 |
| R | 30 |
| N | 10 |

「抽歪 10 次换 1 张想要的」，保底体验成立。

## 5. 架构落点

| 文件 | 改动 |
|---|---|
| `js/games/sudoku/09-gacha.js` | **新增**。卡池定义、抽卡与保底逻辑、图鉴页与卡面渲染 |
| `js/games/sudoku/01-store.js` | `state` 加 `wallet`；新增 `addPoints / draw / unlockSkin / addShard` 等 API |
| `js/games/sudoku/08-app.js` | `onWin()` 里结算点数；首页加「图鉴」入口；皮肤应用到 `document.documentElement` |
| `css/app.css` | 卡面、图鉴网格、抽卡动画；五套皮肤的主题变量组 |
| `index.html` | 加一行 `<script src="js/games/sudoku/09-gacha.js"></script>`；首页加一个 `home-item` |
| `assets/cards/` | **新增**，放立绘 |

`wallet` 结构：

```js
wallet: {
  points: 0,
  shards: 0,
  owned: {},        // { cardId: 张数 }
  skins: [],        // 已解锁皮肤 id
  tickets: 0,       // 补签券
  pity: 0,          // 距大保底还差几抽
  drawCount: 0,
  seenGrids: {},    // 题面指纹 → 首通时间戳（防刷）
}
```

`read()` 已经用 `Object.assign` 兜默认值，`state` 加字段不会让老存档崩。

### 必须避的坑

卡池数据**不能放在 .json 里用 fetch 读**。项目要支持双击 `index.html` 直接玩，`file://` 协议下 `fetch` 本地文件会被同源策略拦掉。所以 manifest 必须**内联写成 js 常量**，和现有的 `SD.Bank.LIST`、`SD.Techniques.LIST` 保持一致。图片走相对路径不受影响。
