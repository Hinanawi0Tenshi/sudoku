# 益智游戏合集

一个纯前端的本地益智游戏合集，目前收录七款：**数独 · 杀手数独 · 扫雷 · 数字华容道 · 2048 · 华容道 · 数织**。
没有账号、没有服务器、没有埋点，所有数据只存在你自己的浏览器里。

## 快速开始

**方式一（推荐，功能完整）**

双击 `启动数独.cmd`。脚本会起一个本地静态服务并自动打开浏览器。
图片识别需要 Web Worker 和 fetch 读取本地文件，浏览器不允许在 `file://` 下做这些事，
所以要用到图片识别就必须走 http。

**方式二（不想起服务）**

直接双击 `index.html`。出题、提示、技巧教学、统计、导入导出、主题切换都能正常用，
只有「图片识别」标签页会提示不可用。

## 七款游戏的数据怎么分

**各存各的。** 一款游戏的进度、战绩、题库不会被另一款游戏的「清除数据」顺手带走——
那是玩家最容易受伤的操作，也是最难解释的一种数据丢失。

| | 存在哪 | 说明 |
|---|---|---|
| 主题 | 全局 | 显示偏好，不是游戏进度。各游戏各记一份的话，换游戏就得重挑一次外观 |
| 通关点数 | 全局 | 七款游戏之间**唯一**互通的东西。在哪款游戏里通关都累加，账本是一个 |
| 数独的设置 / 战绩 / 存档 / 题库 / 图鉴 | `sudoku-studio:v1` | key 保持原样，玩家已有的记录一个字节都没动 |
| 扫雷的设置 / 战绩 / 每日记录 / 存档 | `puzzle-hub:mines:v1` | 在「我的」页里清扫雷成绩，清不掉数独的任何东西 |
| 杀手数独的设置 / 战绩 / 每日记录 / 存档 | `puzzle-hub:killer:v1` | 同上，各存各的 |
| 全局命名空间 | `puzzle-hub:global:v1` | 主题、点数、迁移记录 |

点数按难度分档发放（入门 5 / 简单 10 / 中等 20 / 困难 35 / 大师 60，每日挑战 ×1.5）。
用提示或自动求解**不打折**：这是练习工具，用提示恰恰是它该被用的方式。

## 功能（数独）

### 玩法
- 5 档难度（入门 / 简单 / 中等 / 困难 / 大师），难度**不是按线索个数猜的**，
  而是按「人类最少需要用到哪一级技巧」评出来的。
- 键盘、鼠标、触摸三通；桌面和手机都是同一套交互。
- 铅笔标记（笔记）：笔记态下，选中格已有的候选会在数字键盘上点亮，照着补删很方便。
- 一键笔记：按当前盘面把所有空格的候选数一次铺满（设置里另有「落子后自动更新候选」）。
- 数字填满 9 个后自动从键盘隐藏，不再占位也不用再看计数。
- 撤销 / 重做（400 步）、即时纠错、检查全盘、自动求解。
- 计时器、进度自动保存（换设备不同步，这是刻意的取舍）。

### 每日挑战
- 从数独首页进（或按 `D`），题目由**当天日期作种子**生成——同一天全世界拿到的是同一道题。
- 难度在 L2–L3 之间按日期定，不会太难也不会太简单。
- 对局中状态栏第一格会变成「今日 2026-10-13」，一眼看得出在做哪一天。
- 连续天数自动累计；做完再点可以「再玩一次」重开同一道题。

### 主题
7 套配色，设置面板里挑，对**整个合集**生效：

| 主题 | 说明 |
|---|---|
| 跟随系统 | 按系统的深浅色偏好自动切 |
| 纸白 | 默认浅色 |
| 薄荷 | 偏绿的冷调 |
| 黄昏 | 暖色，久看不累 |
| 夜航 | 默认深色 |
| 墨黑 | 纯黑高对比，黑白 OLED 屏省电 |
| 深林 | 墨绿深色 |

每套主题只覆盖 CSS 变量，组件样式里不写死任何颜色，所以换肤不会漏掉任何角落。

### 手机
- 窄屏自动改成单栏，标题和开关各占一行，状态条压成可横向滑动的一行。
- **数字键盘吸在屏幕底部**：读提示、翻面板的时候随时能填数。
- 按钮与开关的触控目标不小于 40px，格子里数字和铅笔标记在窄屏上另放大一档。
- 适配 iPhone 底部安全区（`env(safe-area-inset-bottom)`）。

### 高亮
- 选中格高亮同行、同列、同宫，以及盘上所有相同数字。
- 冲突数字即时标红；填错的数字保留在盘上并标红，不会自动擦掉。
- 提示时：需要删候选的格子红底，技巧盯着的格子蓝底，两者都有坐标指示。

### 提示与算法教学
27 种人类解题技巧，每一种都带完整的原理、步骤和常见误区：

| 等级 | 数量 | 技巧 |
|---|---|---|
| L1 基础 | 2 | 唯一余数法、隐性唯一余数 |
| L2 排除 | 2 | 宫区块摒除、行列区块摒除 |
| L3 进阶 | 2 | 显性数对、隐性数对 |
| L4 高级 | 5 | 显性三数组、隐性三数组、X-Wing、XY-Wing、空矩形 |
| L5 专家 | 16 | 显性 / 隐性四数组、三链列、四链列、唯一矩形、W 翼、带鳍鱼、退化鱼、XY 链、各类强制链、组合链、试数等 |

点「提示」打开提示面板。面板会**把当前盘面所有能用的解法一次列全**，
按技巧等级从低到高排好：

- 顶部 `‹ 1 / 9 ›` 翻页；
- 讲解里的坐标写成 **【R6C6】** 这样的可点样式，鼠标停上去（或手机上长按）
  就在棋盘上把那一格点亮，不用自己在盘上找；
- 中间一排技巧名，点哪个就看哪个的讲解，选中时棋盘上会预演高亮；
- 下方是选中那一条的完整讲解：
  **这一步是怎么看出来的**（针对当前盘面逐条推导）→ **技巧原理** → **怎么用** →
  **结论** → **常见误区**。

「只讲解」只看不改，「讲解并执行」会把这步落到盘面上。
排序从低到高是刻意的：先用简单技巧走，实在推不动了再上高级技巧。
等级上限可以调低（比如锁在 L1），用来强制自己只用朴素技巧。

### 图片识别
- 拖拽 / 选择 / 直接 `Ctrl+V` 粘贴截图。
- **自动定位网格**：局部对比度找暗线 → 按面积滤掉噪点 → 取最大连通域 →
  凸包 → 穷举最贴合的四边形。歪着拍、强透视都能定位（实测角点误差 6–19px / 760px）。
- 四个角可以手动拖动微调，自动定位不准时以手动为准。
- **透视校正**：单应变换把歪斜的四边形拉正成正方形。
- **网格复检**：校正后重新量一次真实框线——手动对齐不可能像素级精确，
  与其假设四边形贴合，不如直接量图里最长的暗线。
- **识别**：逐格二值化 + 单字符模式 OCR；读不出的格子去掉白名单再试一次。
- **印刷体线索和手写小字笔记会分开**：按墨迹尺寸分簇，笔记不会被当成题面读进去。
- 低置信度的格子标黄，人工点一下就能改。
- **导入前体检**：检查重复数字、有没有解、解是否唯一，并按人类技巧自动分级。
  不合格的题面会被拦下来，不会让你拿到一道无解或多解的棋局。
- **手动填题**：拍不了平整的照片时，照着一张模糊的图把数字敲进去，
  比对着图在纸上重抄一遍快。识别和手填最后汇到同一套校验与导入流程。

**实测准确率**（`tests/ocr-test.js` 端到端跑真实管线）：

| 场景 | 结果 |
|---|---|
| 干净合成图 | 32/32 正确，0 误识，0 漏识 —— 100% |
| 透视 + JPEG 压缩 + 传感器噪声 + 污点 | 约 25% 直接正确，其余标黄待确认 |

第二行是**故意做的压力测试**：把网格投到歪斜四边形上再压成 JPEG 0.85，
叠上噪声和污点，相当于「手机拍报纸」的劣化效果。这种情况下准确率取决于拍摄质量，
所以设计上是**不追求全自动**：低置信度的格子一律标黄等人工确认，导入前还能逐格改。
宁可让人多看一眼，也不要往棋盘里塞错数字。

### 数据
- 导出：题面纯文本（带 3×3 分隔线）、对局 JSON（保留进度和笔记）、棋盘 PNG。
- 导入：题面文本、对局 JSON。导入前一律先体检。
- 统计从「我的」进：总对局 / 胜率 / 分难度战绩 / 技巧使用分布 / 每日挑战纪录。
- 所有数据只存在本机浏览器里，不上传任何服务器。

## 功能（杀手数独）

### 玩法
- 一个已知数都不给。整个盘面被切成若干块「笼子」，每块标着一个和：笼内数字加起来必须等于它，而且笼内数字不能重复。
- 行列宫的老规矩照旧。棋盘、输入、笔记、撤销、存档和数独用的是同一套。
- **选中一格会把整个笼子一起点亮**——「这一格属于哪个笼子」是每一步都要看的信息，靠肉眼顺着虚线找太累。

### 出题：先出终盘，再切笼子
先随机出一道完整终盘，再把它切成笼子，和就自动定了。剩下只有一个问题：这样切出来的题唯一解吗？不唯一就换一种切法重来。

笼子越小越容易唯一（实测 2 格笼 83%、5 格笼 20%、6 格笼几乎永远不唯一），所以笼子尺寸上限卡在 4 格。

**切笼子时种子不能随便挑。** 按固定随机顺序处理时，轮到靠后的格子，它的四邻早被分完了，一格都长不出来，直接变成单格笼——实测「中等」档平均每局 15.7 个单格笼，整盘碎成一片。改成优先挑「还有未分配邻居」的格子当种子，再加一道收尾把漏掉的单格笼并进相邻笼子，中等档降到 **0.3 个**。

难度阶梯由三样一起定：笼子尺寸范围、切得多碎（roomy）、以及切完实测需要哪一级技巧。入门档**故意**切得碎、留一批单格笼——单格笼等于白送一个数字，整盘靠「笼内定数」就能推完，那才是入门该有的样子；从简单档开始把笼子收干净。各档实测（单格笼数 / 出题耗时）：

| 档位 | 笼子 | 单格笼 | 出题 |
|---|---|---|---|
| 入门 | 1–2 格 | 7.7 | 5ms |
| 简单 | 1–3 格 | 0.1 | ~1s |
| 中等 | 1–3 格（收干净） | 0.3 | ~0.9s |
| 困难 | 2–4 格 | 0.0 | ~0.3s |
| 大师 | 2–5 格 | 0.0 | ~0.2s |

### 提示：笼子族 + 标准族
数独那 27 种技巧在杀手盘面上**照样成立**——它们的推理只依赖行列宫候选数，而那个集合永远包含真解数字；多一层笼子只会让真实候选更小，不会让结论失真。所以整族直接复用，讲解也共用同一份。

杀手特有的十二条：

| 等级 | 技巧 |
|---|---|
| L1 | 笼内定数：笼子里只剩一格没填，这一格就是还差的那个和 |
| L2 | 笼内组合：把「k 个不同数字、和为 S」的组合列全，从没出现过的数字全部划掉 |
| L2 | 笼内必含：某个数字在每种组合里都出现，且整个笼子落在同一单元内 → 向该单元外排除 |
| L2 | 组合互斥：组合本身合法，不代表摆得进这些格子。「一个数字占一格」是一次二分匹配，配不上的组合整条划掉 |
| L3 | 少解笼子组合：组合只剩两三种时，逐格算「所有可行摆法里它只可能是几」，往往直接定数 |
| L3 | 笼子分割：笼子横跨单元时，落在单元里的那一段和虽然没定，但有范围，拿它卡候选 |
| L3 | 宫线笼减：跨出单元的那一头填满了，探进来那一段的和就定了 |
| L3 | 45 法则 · 内格：单元里「完全落在里面」的笼子和，45 减它就是剩下那些格子的和 |
| L3 | 45 法则 · 外格：与单元相交的笼子若盖满该单元，Σ笼和 − 45 就是探出去那几格的和 |
| L4 | 笼子比较：两个笼子整个落在同一单元里。一个笼子的某种摆法若让另一个笼子所有组合都撞数字，这种摆法不可能 |
| L4 | 奇偶规则：两格和为奇数，这两格就一奇一偶；配合奇偶掩码删候选 |
| L5 | 笼内试数：假设某格取某个数，用带笼子约束的求解器重算整道题，无解就删掉这个候选 |

评级时 **L5 的笼内试数不参与等级计算**：它强到只要一用就必然通关，算进去的话几乎所有题都会落到 L5，等级这一维就彻底没有分辨力了。所以「等级」只看靠人类技巧能走到哪一级，「必须试数」单独作为最高一档。

### 教程
十二条技巧各配一个当场能触发的演示盘面。演示局面是求解器自己打出来的真实对局，
所以不会出现「图上画的和实际对不上」。

这些局面是**离线算好、当静态数据发出去的**（js/games/killer/08-demos.js，由
tests/build-killer-demos.js 生成）。它们跟玩家、跟时间都没关系，同一份数据对所有人都成立——
原先在浏览器里现算，点开教程要等好几秒，现在展开是瞬时的。
单测里有一条会逐个验证这些局面仍然成立（技巧触发得了、结论和真解一致），数据过期会立刻失败。

生成脚本不能只跟着正常解题顺序走：稀有技巧（笼子分割、宫线笼减、奇偶规则）在前面二十步就被
便宜技巧抢光了，永远轮不到。所以它每到一个局面就主动对每条还没找到的技巧问一遍「你现在能用吗」，
命中就存；再照常走一步。这样十二条才凑得齐。

### 两处被性质测试逼出来的修正

**唯一矩形整族被排除。** 它靠「致命模式」论证：某个形状一旦出现，交换两格就能得到第二个解，所以它不能出现。但杀手多了一层笼子和——交换很可能破坏笼和，「第二个解」根本不存在。这个形状可以合法地待在唯一解盘面上，照搬会删掉真解数字。测试跑出「唯一矩形删掉了真解」，于是整族被排除。

**45 法则算外格时不能要求数字互不相同。** 内格同属一个单元，数字必然不同；但外格是跨笼子的，分属不同笼子，完全可以是同一个数字。第一版拿「互不相同的组合表」去过外格，过约束，删掉了真解。现在两者分开：内格用组合表，外格用「允许重复」的区间判定。

### 看不清分块？两个视觉上的坑

**宫底色和笼子边框抢注意力。** 数独里「相邻宫交替淡底」是分辨 3×3 的锚点，但杀手盘面上它看起来就像分组，反而让人看不清笼子到底怎么划的。带笼子渲染时干脆不画它，只留粗宫线。

**笼子虚线画得太淡。** 去掉宫底色之后笼子边框成了唯一的划分依据，于是从 1.5px / 36% 提到 2px / 52%。

**笼子虚线和九宫格粗线糊成一条。** 两者都贴着格子边画，叠在一起就分不清哪条是哪条。现在笼子虚线**内缩 2px**、缩在格子里画，和格子线之间留出一道缝。

试过「每条笼边只画一次」想省掉相邻笼子之间的平行线，结果那条线归了邻居的笼子——从本笼子看，上、左在自己轮廓里，下、右跑到隔壁去了，看着就像缺了两面。所以每个格子四面该画的边都画，**每个笼子都保证有自己完整的内缩轮廓**；边界处多一条平行虚线是可以接受的代价。单测和一次性的页面检查都会核对轮廓闭合。

## 功能（扫雷）

**未扫格做成 XP / Win7 那种凸起按钮。** 原先未扫格用 `--surface-2`、已扫格用 `--surface`，两者几乎一个色，只能靠 1px 内阴影分辨——实测根本分不出来。现在未扫格是灰色面 + 左上 2px 高光 / 右下 2px 阴影的斜面，已扫格压平留白。配色用 `color-mix` 从主题变量组合出来，7 套主题自动都成立。


### 玩法
- 经典三档（初级 9×9/10 雷、中级 16×16/40 雷、高级 30×16/99 雷），也可以自己定宽高和雷数。
- **首点必安全**：第一次点到哪，那一格连同周围八格都不会有雷，开局不会一点就炸。
- 桌面：左键翻开、右键插旗、双击已翻开的数字快速展开周围。
- 手机：点击翻开、长按插旗；也可以打开「插旗模式」改成点击即插旗。
- 计时、各档最佳成绩、进度自动保存。

### 提示是推理，不是报答案
九种技巧分五级，和数独一个路子：

| 等级 | 技巧 |
|---|---|
| L1 基础 | 单格规则：数字要的雷已经标全 → 其余未知格安全；剩余格数正好等于剩余雷数 → 全是雷 |
| L2 排除 | 全局雷数：剩余雷数把整片未知区域定死 |
| L3 进阶 | 子集规则：两个数字的范围互相包含时，差集能直接判定。1-2-1、1-2-2-1 都是它的特例 |
| L4 高级 | 枚举求解：把所有可能的布雷方式穷举一遍，逐格算「必然安全 / 必然是雷」 |
| L5 专家 | 概率猜测：真推不动时，给出雷概率最低的那一格 |

**每一条「必然」结论都是可证明的**：说某格安全就一定安全，说某格是雷就一定是雷。
测试里有一条性质测试盯着这件事——随机打 180 局，求解器给出的每一个必然结论都拿去和真实雷分布逐个比对。
真推不动时，提示会明确标成「这一步是猜的」，并给出每一格的准确雷概率，不把猜测混进必然结论里。

枚举的做法值得一提：边界格按共享约束拆成互不相干的连通分量各自穷举，再用卷积把各分量组合起来，
只保留「总雷数正好等于剩余雷数」的组合；剩下那些不挨着任何数字的「深海格」彼此完全对称，
用组合数一次算掉，不需要也不应该一个个枚举（480 格穷举是 10^144 量级）。

### 教程
九种技巧各配一个当场能触发的演示盘面，点开哪一条就算哪一条的演示。

演示局面是**运行时现算的**：让求解器随机打对局，打到能触发这条技巧的局面就停下，存下来复用
（九种全算一遍要好几秒，而玩家一次只看一种）。随机对局里实在遇不到的规则退回手工摆的构造示例，
文案会直说是「手工摆出来的」，不假装成真对局。演示盘面只读、不接受点击，只高亮这条推理涉及的格子。

### 每日挑战
难度固定中级，**整张图完全由日期决定**。普通对局的首点是玩家自己点的，
而布雷要避开首点周围，所以同一颗种子换个位置点就是另一张图；
每日挑战因此把首点也交给日期决定并预先翻开——这样「同一天全世界同一张图」才真的成立。

### 关于猜测
高级盘面上纯逻辑能走完的比例大约六成，剩下的要靠猜。这是扫雷本身的难度，不是提示做得不够。
枚举能算出每一格的准确雷概率，所以「猜」也是有依据的：挑概率最低的那格，而不是凭感觉。

## 功能（数织）

| 能力 | 说明 |
|---|---|
| 五档难度 | 5×5 / 10×10 / 15×15 / 20×20 / 需假设 |
| 操作 | 点格子填实心；按住拖拽可批量填/擦（操作类型由第一格决定）；「标记」模式下点格子打叉；桌面右键直接打叉 |
| 撤回 | 一次操作（一划/一点）一档，不是一格一档；Ctrl+Z 也行 |
| 提示 | 定位到具体某一行/列，用「唯一摆法 / 重叠法 / 排除法」讲清这一步是怎么来的 |
| 画册 | 解出过的图会记下来，可以回头再玩同一幅 |

### 画是从哪来的

**这是数织最核心的设计问题，因为数织和别的品类反过来：先有画，线索是从画里读出来的。**
随便生成一张网格当不了题目——线索太弱的图会推出多个解，或者根本推不动。

所以图库里每一张都**离线验过两件事**：

1. **解唯一** —— 用求解器数解的个数，多于一个的直接淘汰
2. **光靠行列推理能不能推完** —— 推不完的归到「大师」档（解是唯一的，但必须假设才能推进）

实测 41 张图：**0 张多解**，37 张纯逻辑可解，4 张需要假设（五角星、巨型五角星、斜叉、大斜叉）。

图分两类：

- **几何图形用公式画**（爱心、星星、圆环、菱形、三角、十字、箭头、六边形、斜叉），任意尺寸都能生成且不走样
- **具体物件手绘成字符画**（房子、树、猫脸、蘑菇、帆船、苹果、皇冠、笑脸、钥匙、杯子）——公式画不出「像猫」这种东西

形状本身也踩过坑：三角第一版条件写反了画成窄条，六边形画成了圆角矩形，爱心的凹口太浅看着像圆疙瘩，钥匙的线索太弱有两个解——都是靠「打印出来看 + 跑一遍验证」发现的。

**图形必须裁到外接矩形。** 不裁的话四周会留出整行整列的空格，那些行列的线索是 0，
盘面上冒出一堆 0，玩家会以为线索丢了。实测 41 张里有 **23 张**是这样。
裁过之后长宽不再相等（菱形 20×20 变成 16×18），这是正常的——数织本来就可以是长方形。

裁完还剩一张有问题：**杯子**。原来画成「杯身 | 空一列 | 把手」，中间那列整列是空的，
而裁图裁不掉**内部**空列。改成细把手之后又变成多解（把手的位置摆法不唯一）。
最后用粗方把手，两种毛病都没有。

### 提示为什么是必然结论

数织的提示和数字华容道/2048 不一样：它说的是**「这格一定是实心」**，不是建议。说错了玩家后面全盘跟着错。

依据是行求解器的完备性：把这一行线索的**所有**合法摆法枚举出来逐格统计，凡是每种摆法都盖住的格子，在真解里必然也是实心（前提是玩家目前填的格子都对）。

单测里有一条性质测试专门盯这个：**逐格核对提示的每一条结论和真解是否一致**，1721 步零冲突。

## 功能（华容道）

| 能力 | 说明 |
|---|---|
| 五档难度 | 入门 / 简单 / 中等 / 困难 / 大师，按**最短步数**分档 |
| 操作 | 按住块往空位方向拖；也可以点选后按方向键；只点不拖且只有一个方向能动时自动走一步 |
| 提示 | **永远是最优解**——沿最短路径走一步 |
| 成绩 | 步数优先，步数相同再看用时 |

**这个游戏有一个别处没有的便利：可达局面只有两万多个。**

所以开局时把**所有局面到出口的最短步数**一次性算出来（两遍广度优先，约 0.1 秒），之后：

- **提示** = 沿最短路径走一步，永远最优，不存在「算不动就退而求其次」
- **难度** = 最短步数，精确值，不是估的
- **出题** = 按距离区间筛一个局面出来，不用「切、验、评级」三步

**为什么是两遍 BFS 而不是枚举目标族。** 目标不是一个局面，而是「曹操在底部中间」的一整族（964 个）。直觉做法是把它们全枚举出来当源，但实测**枚举本身要 1.4 秒，比 BFS 本体（0.32 秒）贵四倍还多**。换成先从经典开局 BFS 一遍找出所有可达状态，再从里面挑出目标态当第二遍的源——两遍加起来 0.1 秒，枚举整块省掉。

**局面键按形状编码，不按块身份。** 四个卒互换、两个竖块互换，对玩家是同一个局面；不合并的话状态数会白翻好几倍。

经典布局「横刀立马」的最短解是 **116 步**（按走一格算一步），在最高档里。

## 功能（2048）

| 能力 | 说明 |
|---|---|
| 三档难度 | 3×3（目标 256）/ 4×4（2048）/ 5×5（4096） |
| 操作 | 方向键 / WASD，手机上直接滑 |
| 提示 | 期望最大化给出四个方向的期望分，按分排序 |
| 成绩 | 各档最高分分开存；打到目标算通关但可以接着打 |

**动画分两拍**：先把源格子的牌平移到目标位置（CSS transition 负责"滑过去"），
过渡结束后按新盘面重建，给合并出来的牌和新落的牌弹一下。
第二拍敢整块重建，是因为第一拍结束时那些牌**已经在目标位置**了，重建出来的节点落在同一个地方，看不出跳变。

**提示写「建议」不写「最优」。** 2048 每一步都有随机成分（新牌落哪、是 2 还是 4），
不存在「这一步之后必胜」的走法。求解器用的是期望最大化：玩家节点取最大，随机节点按 0.9 / 0.1 加权取平均。
它给的是**期望分最高**的方向——把它写成结论，比不给提示更糟。

**估值权重**：空位数最高（留着空位才有腾挪余地），单调性次之（让牌沿着一个方向从大到小排开），
平滑度再次（相邻牌数值别差太远）。实测深度 3 平均 1ms，用它自己打一局能稳定过 1024。

## 功能（数字华容道）

| 能力 | 说明 |
|---|---|
| 三档难度 | 3×3 / 4×4 / 5×5，打乱步数递增 |
| 键盘 | 方向键把空格那一侧的数字推过来 |
| 提示 | 3×3 给**最优下一步**（A* 精确）；4×4 以上带节点上限试搜，算不动就退成**就近一步**并在弹窗里写明不保证最短 |
| 成绩 | 按步数排名，步数相同再看用时；各档最好成绩分开存 |
| 存档 | 中途离开自动保存，回来接着推 |

**打乱是「从终局倒着走」而不是随机排列。** 随机排列有一半概率无解（逆序数的奇偶性决定），
还得额外判一次；倒着走出来必然有解，走的步数还顺便当了难度旋钮。

**提示分两档是刻意的，不是没做完。** 滑块不像数独有「逻辑上被迫」的一步，本来就只有建议。
4×4 最优解常要 50 步以上、5×5 上百步，状态数分别是一万亿和一万亿亿级别，实时搜不完。
把「算不动就降级」如实说出来，比拿贪心冒充最优解强。

**降级那一档踩过一个大坑：提示会来回打转。** 最初的写法是一歩贪心（挑曼哈顿距离降最多的那步），
卡在局部最优时所有走法都是负收益，并列又取了第一个候选——于是提示先说「把 10 往上滑」，
照做之后立刻改口「把 10 往下滑」，**两个方向互相抵消，实测能无限循环**。

修的过程本身值得记：

| 试过的写法 | 结果 |
|---|---|
| 一歩贪心，并列取第一个 | 无限循环（10 → 10 → 10 → …） |
| 并列时优先「不动已归位的块」 | 还是循环，换成了另一块牌 |
| 加「不许撤销上一歩」但只当**并列时的次要条件** | 无效——回退那步往往恰好 delta 最高 |
| 记住「上一歩挪的是哪块牌」 | 无效——走完之后那块牌已经不在原来的下标上了 |
| 改成「往后看 k 步，取**能达到最低总距离**的第一步」 | 不再打转，5×5 也能推进 |
| 禁忌表当**硬约束**（邻居全禁光就没得选） | 漏掉周期 2 |
| **禁忌表当软约束 + 「不许撤销上一歩」当硬约束** | **周期 2 清零** |

关键认识：**周期 2 一定表现为同一块牌来回挪**，所以「不许撤销上一歩」必须是硬约束
（空格的邻居至少两个，禁掉一个仍有得走）；而「禁忌表」只能当软约束——做成硬的话
邻居一被禁光就没得选，只能放开，防打转就漏了。

修完实测：3×3 与 4×4 全部解出且零打转，5×5 平均把总距离降 82%、零打转。
单测里有一条回归专门盯周期 2。

## 出题逻辑

单纯「挖到不能挖」得到的题往往只要唯一余数就能解完；单纯「挖到只剩 N 个数」又可能无解。
所以这里用**定向挖洞**：

每挖掉一格，同时评两次分——
- 高阶技巧（L1..L_max）还能不能解？解不动就拒绝这格（否则就成了一道要瞎猜的题）。
- 低阶技巧（L1..L_k）还能不能解？解不动了就说明达到了目标难度，收工。

所有尝试都失败时，退回到「最高可评级」的那一道，并保证它至少能被 L1..L5 完整解完。
**宁可难度低一点，也不出一道需要试错的题。**

## 部署上线

线上地址：**https://sudoku-studio.app.workbuddy.host/**
locator 记在 `.workbuddy/applications.yaml`。

纯静态站，平台自带 HTTP 服务，`serve.py` 只是给你本地双击用的，部署用不上。
同一个目录重新发布就是**原地覆盖**，链接不变，之前分享出去的地址继续有效。

改完代码后发布，然后**跑一遍校验**——不要拿"发布成功"当结论：

```powershell
node tests/verify-live.js
```

它把 index.html / css / js 逐个下载回来比对 md5（整个站点二十来个文件，几秒跑完），
全部一致且退出码 0 才算真的生效。

两个坑记在这里：

- **手工核对必须带时间戳**。边缘节点会缓存，刚发完立刻 `curl` 拿到的是旧文件，
  md5 对不上，看着像发布失败，其实文件已经上去了：
  ```bash
  curl -L "https://sudoku-studio.app.workbuddy.host/js/games/sudoku/03-panels.js?t=$(date +%s)"
  ```
- **别把站点挪到子目录**。`index.html` 里所有资源都是相对路径（`js/…`、`css/app.css`），
  页面必须和这些目录同级，否则整站 404。

### 哪些东西会公开

发布是把整个目录传上去（只排除 `.git/`、`node_modules/`、构建产物），
实测下面前几项在公网可以直接访问：

| 路径 | 状态 |
|---|---|
| `.workbuddy/memory/`、`.workbuddy/skills/` | 公开（工作笔记、技能文档都会被人读到）|
| `tests/`（测试脚本、截图） | 公开 |
| `README.md`、`serve.py` | 公开 |
| `.git/` | 403，取不到 |

所以**别往这个项目里写密钥、token 或未公开的素材**，包括 `.workbuddy/` 里的记忆文件。

给负责写代码的 agent 看的完整操作手册在 `.workbuddy/skills/sudoku-deploy/SKILL.md`，
里面有发布参数、同意规则和完整的踩坑清单。

## 一些实现上的取舍

**为什么自己做识别器，不用 Tesseract**
Tesseract 会把相邻的数字合并成一个 word，按词中心定位必然错位；切成单字符又得带上 17MB 的
wasm 和语言包，还要额外写 worker。现在换成自己的一套：动态合成字体特征库（12 字体 × 3 种横向
缩放）+ 拓扑孔洞数 + 长宽比，用余弦相似度打分排序。纯 JS、零外链、`file://` 双击也能跑，
项目体积从 40MB 降到 21MB。干净图、印刷题面 + 铅笔笔记、手机照片三种场景都是 100%。

**先把瓶颈量清楚，再谈换算法**
照片场景一度只有 25%。当时的判断是「JPEG 压缩 + 透视重采样把笔画糊了，得上 OpenCV.js」。
真去量了才发现是单应变换的映射方向写反了——拿输出坐标去映射输入，等于反向缩放，
棋盘在结果图里只占 68%。改一行，25% → 97%。换算法解决不了方向错误，
但换算法看起来像在解决问题。

**为什么校正后还要复检网格**
手动拖四个角不可能像素级贴合，照片里也有透视残留。与其相信四边形假设，
不如在校正图里重新量一次真实框线——这一步让合成测试从 94% 提到 100%。

**为什么填错了不自动擦掉**
填错就自动撤销，玩家根本不知道自己错了、错在哪。改成保留 + 标红，
让人看见自己填了什么，再决定要不要改。

**为什么移除了 XYZ-Wing**
写完之后发现推导不出可靠的结论。错误的提示比没有提示更糟：
它会让人沿着一条错路走下去。所以宁可少一种技巧，也不发不可信的提示。

**为什么没有用染色（Coloring）技巧**
同样的原因——无法给出可证明的判定条件，就不实现。
`js/core/05-techniques.js` 里每条技巧的注释都写明了成立条件与推导，
可以逐条复核。
