# 益智游戏合集

一个纯前端的本地益智游戏合集，目前收录三款：**数独 · 杀手数独 · 扫雷**。
没有账号、没有服务器、没有埋点，所有数据只存在你自己的浏览器里。

## 快速开始

**方式一（推荐，功能完整）**

双击 `启动数独.cmd`。脚本会起一个本地静态服务并自动打开浏览器。
图片识别需要 Web Worker 和 fetch 读取本地文件，浏览器不允许在 `file://` 下做这些事，
所以要用到图片识别就必须走 http。

**方式二（不想起服务）**

直接双击 `index.html`。出题、提示、技巧教学、统计、导入导出、主题切换都能正常用，
只有「图片识别」标签页会提示不可用。

## 三款游戏的数据怎么分

**各存各的。** 一款游戏的进度、战绩、题库不会被另一款游戏的「清除数据」顺手带走——
那是玩家最容易受伤的操作，也是最难解释的一种数据丢失。

| | 存在哪 | 说明 |
|---|---|---|
| 主题 | 全局 | 显示偏好，不是游戏进度。三款游戏各记一份的话，换游戏就得重挑一次外观 |
| 通关点数 | 全局 | 三款游戏之间**唯一**互通的东西。在哪款游戏里通关都累加，账本是一个 |
| 数独的设置 / 战绩 / 存档 / 题库 / 图鉴 | `sudoku-studio:v1` | key 保持原样，玩家已有的记录一个字节都没动 |
| 扫雷的设置 / 战绩 / 每日记录 / 存档 | `puzzle-hub:mines:v1` | 在「我的」页里清扫雷成绩，清不掉数独的任何东西 |
| 杀手数独的设置 / 战绩 / 每日记录 / 存档 | `puzzle-hub:killer:v1` | 同上，各存各的 |
| 全局命名空间 | `puzzle-hub:global:v1` | 主题、点数、迁移记录 |

点数按难度分档发放（入门 5 / 简单 10 / 中等 20 / 困难 35 / 大师 60，每日挑战 ×1.5）。
用提示或自动求解**不打折**：这是练习工具，用提示恰恰是它该被用的方式。

## 功能（数独）

### 玩法
- 5 档难度（入门 / 简单 / 中等 / 困难 / 大师），难度**不是按线索个数猜的**，
  而是按「人类最少需要用到哪一级技巧」评出来的。
- 键盘、鼠标、触摸三通；桌面和手机都是同一套交互。
- 铅笔标记（笔记）：笔记态下，选中格已有的候选会在数字键盘上点亮，照着补删很方便。
- 一键笔记：按当前盘面把所有空格的候选数一次铺满（设置里另有「落子后自动更新候选」）。
- 数字填满 9 个后自动从键盘隐藏，不再占位也不用再看计数。
- 撤销 / 重做（400 步）、即时纠错、检查全盘、自动求解。
- 计时器、进度自动保存（换设备不同步，这是刻意的取舍）。

### 每日挑战
- 从数独首页进（或按 `D`），题目由**当天日期作种子**生成——同一天全世界拿到的是同一道题。
- 难度在 L2–L3 之间按日期定，不会太难也不会太简单。
- 对局中状态栏第一格会变成「今日 2026-10-13」，一眼看得出在做哪一天。
- 连续天数自动累计；做完再点可以「再玩一次」重开同一道题。

### 主题
7 套配色，设置面板里挑，对**整个合集**生效：

| 主题 | 说明 |
|---|---|
| 跟随系统 | 按系统的深浅色偏好自动切 |
| 纸白 | 默认浅色 |
| 薄荷 | 偏绿的冷调 |
| 黄昏 | 暖色，久看不累 |
| 夜航 | 默认深色 |
| 墨黑 | 纯黑高对比，黑白 OLED 屏省电 |
| 深林 | 墨绿深色 |

每套主题只覆盖 CSS 变量，组件样式里不写死任何颜色，所以换肤不会漏掉任何角落。

### 手机
- 窄屏自动改成单栏，标题和开关各占一行，状态条压成可横向滑动的一行。
- **数字键盘吸在屏幕底部**：读提示、翻面板的时候随时能填数。
- 按钮与开关的触控目标不小于 40px，格子里数字和铅笔标记在窄屏上另放大一档。
- 适配 iPhone 底部安全区（`env(safe-area-inset-bottom)`）。

### 高亮
- 选中格高亮同行、同列、同宫，以及盘上所有相同数字。
- 冲突数字即时标红；填错的数字保留在盘上并标红，不会自动擦掉。
- 提示时：需要删候选的格子红底，技巧盯着的格子蓝底，两者都有坐标指示。

### 提示与算法教学
27 种人类解题技巧，每一种都带完整的原理、步骤和常见误区：

| 等级 | 数量 | 技巧 |
|---|---|---|
| L1 基础 | 2 | 唯一余数法、隐性唯一余数 |
| L2 排除 | 2 | 宫区块摒除、行列区块摒除 |
| L3 进阶 | 2 | 显性数对、隐性数对 |
| L4 高级 | 5 | 显性三数组、隐性三数组、X-Wing、XY-Wing、空矩形 |
| L5 专家 | 16 | 显性 / 隐性四数组、三链列、四链列、唯一矩形、W 翼、带鳍鱼、退化鱼、XY 链、各类强制链、组合链、试数等 |

点「提示」打开提示面板。面板会**把当前盘面所有能用的解法一次列全**，
按技巧等级从低到高排好：

- 顶部 `‹ 1 / 9 ›` 翻页；
- 讲解里的坐标写成 **【R6C6】** 这样的可点样式，鼠标停上去（或手机上长按）
  就在棋盘上把那一格点亮，不用自己在盘上找；
- 中间一排技巧名，点哪个就看哪个的讲解，选中时棋盘上会预演高亮；
- 下方是选中那一条的完整讲解：
  **这一步是怎么看出来的**（针对当前盘面逐条推导）→ **技巧原理** → **怎么用** →
  **结论** → **常见误区**。

「只讲解」只看不改，「讲解并执行」会把这步落到盘面上。
排序从低到高是刻意的：先用简单技巧走，实在推不动了再上高级技巧。
等级上限可以调低（比如锁在 L1），用来强制自己只用朴素技巧。

### 图片识别
- 拖拽 / 选择 / 直接 `Ctrl+V` 粘贴截图。
- **自动定位网格**：局部对比度找暗线 → 按面积滤掉噪点 → 取最大连通域 →
  凸包 → 穷举最贴合的四边形。歪着拍、强透视都能定位（实测角点误差 6–19px / 760px）。
- 四个角可以手动拖动微调，自动定位不准时以手动为准。
- **透视校正**：单应变换把歪斜的四边形拉正成正方形。
- **网格复检**：校正后重新量一次真实框线——手动对齐不可能像素级精确，
  与其假设四边形贴合，不如直接量图里最长的暗线。
- **识别**：逐格二值化 + 单字符模式 OCR；读不出的格子去掉白名单再试一次。
- **印刷体线索和手写小字笔记会分开**：按墨迹尺寸分簇，笔记不会被当成题面读进去。
- 低置信度的格子标黄，人工点一下就能改。
- **导入前体检**：检查重复数字、有没有解、解是否唯一，并按人类技巧自动分级。
  不合格的题面会被拦下来，不会让你拿到一道无解或多解的棋局。
- **手动填题**：拍不了平整的照片时，照着一张模糊的图把数字敲进去，
  比对着图在纸上重抄一遍快。识别和手填最后汇到同一套校验与导入流程。

**实测准确率**（`tests/ocr-test.js` 端到端跑真实管线）：

| 场景 | 结果 |
|---|---|
| 干净合成图 | 32/32 正确，0 误识，0 漏识 —— 100% |
| 透视 + JPEG 压缩 + 传感器噪声 + 污点 | 约 25% 直接正确，其余标黄待确认 |

第二行是**故意做的压力测试**：把网格投到歪斜四边形上再压成 JPEG 0.85，
叠上噪声和污点，相当于「手机拍报纸」的劣化效果。这种情况下准确率取决于拍摄质量，
所以设计上是**不追求全自动**：低置信度的格子一律标黄等人工确认，导入前还能逐格改。
宁可让人多看一眼，也不要往棋盘里塞错数字。

### 数据
- 导出：题面纯文本（带 3×3 分隔线）、对局 JSON（保留进度和笔记）、棋盘 PNG。
- 导入：题面文本、对局 JSON。导入前一律先体检。
- 统计从「我的」进：总对局 / 胜率 / 分难度战绩 / 技巧使用分布 / 每日挑战纪录。
- 所有数据只存在本机浏览器里，不上传任何服务器。

## 功能（杀手数独）

### 玩法
- 一个已知数都不给。整个盘面被切成若干块「笼子」，每块标着一个和：笼内数字加起来必须等于它，而且笼内数字不能重复。
- 行列宫的老规矩照旧。棋盘、输入、笔记、撤销、存档和数独用的是同一套。
- **选中一格会把整个笼子一起点亮**——「这一格属于哪个笼子」是每一步都要看的信息，靠肉眼顺着虚线找太累。

### 出题：先出终盘，再切笼子
先随机出一道完整终盘，再把它切成笼子，和就自动定了。剩下只有一个问题：这样切出来的题唯一解吗？不唯一就换一种切法重来。

笼子越小越容易唯一（实测 2 格笼 83%、5 格笼 20%、6 格笼几乎永远不唯一），所以难度阶梯靠「笼子切多大」加「切完实测需要哪一级技巧」两条一起定。各档实测：入门 3ms、简单 3ms、中等 25ms、困难 71ms、大师 204ms，都切得到目标难度。

### 提示：笼子族 + 标准族
数独那 27 种技巧在杀手盘面上**照样成立**——它们的推理只依赖行列宫候选数，而那个集合永远包含真解数字；多一层笼子只会让真实候选更小，不会让结论失真。所以整族直接复用，讲解也共用同一份。

杀手特有的六条：

| 等级 | 技巧 |
|---|---|
| L1 | 笼内定数：笼子里只剩一格没填，这一格就是还差的那个和 |
| L2 | 笼内组合：把「k 个不同数字、和为 S」的组合列全，从没出现过的数字全部划掉 |
| L2 | 笼内必含：某个数字在每种组合里都出现，且整个笼子落在同一单元内 → 向该单元外排除 |
| L3 | 45 法则 · 内格：单元里「完全落在里面」的笼子和，45 减它就是剩下那些格子的和 |
| L3 | 45 法则 · 外格：与单元相交的笼子若盖满该单元，Σ笼和 − 45 就是探出去那几格的和 |
| L5 | 笼内试数：假设某格取某个数，用带笼子约束的求解器重算整道题，无解就删掉这个候选 |

### 有一族技巧被主动排除了
唯一矩形靠「致命模式」论证：某个形状一旦出现，交换两格就能得到第二个解，所以它不能出现。但杀手多了一层笼子和——交换很可能破坏笼和，「第二个解」根本不存在。这个形状可以合法地待在唯一解盘面上，照搬会删掉真解数字。

这一条是性质测试逼出来的：测试跑出「唯一矩形删掉了真解」，于是整族被排除。

## 功能（扫雷）

### 玩法
- 经典三档（初级 9×9/10 雷、中级 16×16/40 雷、高级 30×16/99 雷），也可以自己定宽高和雷数。
- **首点必安全**：第一次点到哪，那一格连同周围八格都不会有雷，开局不会一点就炸。
- 桌面：左键翻开、右键插旗、双击已翻开的数字快速展开周围。
- 手机：点击翻开、长按插旗；也可以打开「插旗模式」改成点击即插旗。
- 计时、各档最佳成绩、进度自动保存。

### 提示是推理，不是报答案
九种技巧分五级，和数独一个路子：

| 等级 | 技巧 |
|---|---|
| L1 基础 | 单格规则：数字要的雷已经标全 → 其余未知格安全；剩余格数正好等于剩余雷数 → 全是雷 |
| L2 排除 | 全局雷数：剩余雷数把整片未知区域定死 |
| L3 进阶 | 子集规则：两个数字的范围互相包含时，差集能直接判定。1-2-1、1-2-2-1 都是它的特例 |
| L4 高级 | 枚举求解：把所有可能的布雷方式穷举一遍，逐格算「必然安全 / 必然是雷」 |
| L5 专家 | 概率猜测：真推不动时，给出雷概率最低的那一格 |

**每一条「必然」结论都是可证明的**：说某格安全就一定安全，说某格是雷就一定是雷。
测试里有一条性质测试盯着这件事——随机打 180 局，求解器给出的每一个必然结论都拿去和真实雷分布逐个比对。
真推不动时，提示会明确标成「这一步是猜的」，并给出每一格的准确雷概率，不把猜测混进必然结论里。

枚举的做法值得一提：边界格按共享约束拆成互不相干的连通分量各自穷举，再用卷积把各分量组合起来，
只保留「总雷数正好等于剩余雷数」的组合；剩下那些不挨着任何数字的「深海格」彼此完全对称，
用组合数一次算掉，不需要也不应该一个个枚举（480 格穷举是 10^144 量级）。

### 教程
九种技巧各配一个当场能触发的演示盘面。演示局面是求解器自己打出来的真实对局
（少数几条在随机对局里太罕见，用手工摆的局面），所以不会出现「图上画的和实际对不上」。

### 每日挑战
难度固定中级，**整张图完全由日期决定**。普通对局的首点是玩家自己点的，
而布雷要避开首点周围，所以同一颗种子换个位置点就是另一张图；
每日挑战因此把首点也交给日期决定并预先翻开——这样「同一天全世界同一张图」才真的成立。

### 关于猜测
高级盘面上纯逻辑能走完的比例大约六成，剩下的要靠猜。这是扫雷本身的难度，不是提示做得不够。
枚举能算出每一格的准确雷概率，所以「猜」也是有依据的：挑概率最低的那格，而不是凭感觉。

## 出题逻辑

单纯「挖到不能挖」得到的题往往只要唯一余数就能解完；单纯「挖到只剩 N 个数」又可能无解。
所以这里用**定向挖洞**：

每挖掉一格，同时评两次分——
- 高阶技巧（L1..L_max）还能不能解？解不动就拒绝这格（否则就成了一道要瞎猜的题）。
- 低阶技巧（L1..L_k）还能不能解？解不动了就说明达到了目标难度，收工。

所有尝试都失败时，退回到「最高可评级」的那一道，并保证它至少能被 L1..L5 完整解完。
**宁可难度低一点，也不出一道需要试错的题。**

## 部署上线

线上地址：**https://sudoku-studio.app.workbuddy.host/**
locator 记在 `.workbuddy/applications.yaml`。

纯静态站，平台自带 HTTP 服务，`serve.py` 只是给你本地双击用的，部署用不上。
同一个目录重新发布就是**原地覆盖**，链接不变，之前分享出去的地址继续有效。

改完代码后发布，然后**跑一遍校验**——不要拿"发布成功"当结论：

```powershell
node tests/verify-live.js
```

它把 index.html / css / js 逐个下载回来比对 md5（含 20M 的 OCR 资源），
全部一致且退出码 0 才算真的生效。

两个坑记在这里：

- **手工核对必须带时间戳**。边缘节点会缓存，刚发完立刻 `curl` 拿到的是旧文件，
  md5 对不上，看着像发布失败，其实文件已经上去了：
  ```bash
  curl -L "https://sudoku-studio.app.workbuddy.host/js/games/sudoku/03-panels.js?t=$(date +%s)"
  ```
- **别把站点挪到子目录**。`js/games/sudoku/07-ocr.js` 里 `VENDOR = 'js/vendor/'` 是相对路径，
  部署位置必须和 `index.html` 同级，否则图片识别的 worker 和语言包全部 404。

### 哪些东西会公开

发布是把整个目录传上去（只排除 `.git/`、`node_modules/`、构建产物），
实测下面前几项在公网可以直接访问：

| 路径 | 状态 |
|---|---|
| `.workbuddy/memory/`、`.workbuddy/skills/` | 公开（工作笔记、技能文档都会被人读到）|
| `tests/`（测试脚本、截图） | 公开 |
| `README.md`、`serve.py` | 公开 |
| `.git/` | 403，取不到 |

所以**别往这个项目里写密钥、token 或未公开的素材**，包括 `.workbuddy/` 里的记忆文件。

给负责写代码的 agent 看的完整操作手册在 `.workbuddy/skills/sudoku-deploy/SKILL.md`，
里面有发布参数、同意规则和完整的踩坑清单。

## 一些实现上的取舍

**为什么逐格 OCR 而不是整幅识别**
Tesseract 会把相邻的数字合并成一个 word，按词中心定位必然错位（一格命中全盘偏移）。
改成逐格切图 + 单字符模式后，合成测试从 0% 提升到 100%。
整幅模式保留作兜底，但实测很弱。

**为什么校正后还要复检网格**
手动拖四个角不可能像素级贴合，照片里也有透视残留。与其相信四边形假设，
不如在校正图里重新量一次真实框线——这一步让合成测试从 94% 提到 100%。

**为什么填错了不自动擦掉**
填错就自动撤销，玩家根本不知道自己错了、错在哪。改成保留 + 标红，
让人看见自己填了什么，再决定要不要改。

**为什么移除了 XYZ-Wing**
写完之后发现推导不出可靠的结论。错误的提示比没有提示更糟：
它会让人沿着一条错路走下去。所以宁可少一种技巧，也不发不可信的提示。

**为什么没有用染色（Coloring）技巧**
同样的原因——无法给出可证明的判定条件，就不实现。
`js/core/05-techniques.js` 里每条技巧的注释都写明了成立条件与推导，
可以逐条复核。
